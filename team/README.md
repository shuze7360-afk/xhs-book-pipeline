# 编辑部团队架构说明

本目录是小红书读书笔记流水线"编辑部团队"的**岗位手册源**（single source of truth）。5个专岗 subagent 的注册文件（`~/.zcode/agents/xhs-*.md`）只是薄壳，指向本目录的手册——改岗位行为只改这里。

## 岗位一览

| 岗位 | subagent 注册名 | 类型 | 负责 | 产出 |
|---|---|---|---|---|
| 主编 | （主agent本身） | 编排 | 阶段0、验收各岗、两道人工闸门、阶段6发布、阶段7复盘 | 00-任务书、03-用户真实反应、发布执行、07-复盘 |
| 书探 | `xhs-book-scout` | 生产 | 阶段1-2 搜书/下载/转MD | 01-完整性声明.md + 原书MD |
| 拆书分析师 | `xhs-deep-reader` | 分析 | 阶段3 第一阶段分析+3钢人问题 | 02-第一阶段分析.md（内容返给主编存档） |
| 执笔编辑 | `xhs-ghost-writer` | 生产 | 阶段4 四部分成稿+发布稿 | 04-成稿.md、05-发布稿.md |
| 美编 | `xhs-card-artist` | 生产 | 阶段5a Kami卡片 | cards/*.png |
| 质量审核员 | `xhs-style-checker` | 审核 | 阶段5b 独立合规检查 | 06-质量审核报告.md（内容返给主编存档） |

## 五条设计原则（这套架构真正要学的东西）

1. **编排与执行分离**：主编（主agent）不亲自干活，只做拆任务、派工、验收、和用户对话；专岗只干活，不见用户。
2. **交接靠文件，不靠转述**：每个岗位的输入/输出是一个固定文件名（00~07），派工消息里传路径。好处：任何一岗可重跑、可审计、上下文不膨胀。
3. **上下文隔离**：每个岗位只喂它需要的。美编拿不到原书全文（只拿发布稿），拆书分析师拿不到发布约束（营销腔进不了分析），质量审核员拿不到任何岗位的"自查声明"。
4. **分析岗只读，生产岗落盘**：分析师和审核员的产出由主编验收后存档——主编验收是多agent系统里最便宜的质检点。生产岗直接写文件，减少转手损耗。
5. **闸门永远在主编手里**：两道人工闸门（等真实反应、确认发布）是人机分工的产品设计。subagent 靠手册里的红线自我约束，主编靠流程强制——双保险。

## 降级模式（重要）

如果当前会话里没有注册的 `xhs-*` subagent 类型（比如换了客户端、或注册文件未生效），团队照常运转：用 `general-purpose` subagent 派工，派工消息开头加一句：

> 你的岗位手册在 `<手册绝对路径>`，先完整读一遍，再按手册执行下面的任务。

岗位手册是自足的（含输入契约、流程、红线、输出格式），注册壳只是便利层。

## 怎么改

- **改某岗位的行为**：只改本目录对应手册，注册壳不用动。
- **加新岗位**：① 本目录写手册；② 仓库 `agents/` 写注册壳（frontmatter：`name`/`description`/`tools`/`color`，正文=身份一句+手册路径+铁律"不与用户对话"）并复制到 `~/.zcode/agents/` 完成注册；③ SKILL.md 岗位表加一行。
- **改注册壳**：已安装的在 `~/.zcode/agents/`（不在本 git 仓库，仓库内 `agents/` 是安装源），删除或改名即"裁掉"一个岗位。

## 运行文件夹约定

每次运行开一个目录：`<Obsidian库>/小红书自媒体自动化程序/runs/<YYYY-MM-DD-书名>/`，按 00~07 编号存交接文件，卡片图放 `cards/`。原书 MD 仍存 `书籍原文MD/`（历史约定不变）。
